# Contributing

Thanks for helping. Bug reports, false positives and new checks are all welcome; for anything
large, open an issue first so we can agree on the approach.

## Setup

```bash
uv sync
uv run pytest --cov    # must stay at or above 90% coverage
uv run ruff check . && uv run ruff format . && uv run mypy
```

Tests use [moto](https://github.com/getmoto/moto), so no AWS account is needed. Where moto
doesn't implement an API (CloudTrail `LookupEvents`, CloudWatch Logs `storedBytes`), use
`botocore.stub.Stubber`; see `tests/test_owners.py`.

## Adding a check

1. Write a function `(session, region, config) -> list[Finding]` in
   [`src/costwatch/checks/`](src/costwatch/checks/). Create clients with
   `costwatch.aws.client(...)`, paginate everything, and price with `costwatch.pricing`.
2. Register it in `CHECKS` in [`checks/__init__.py`](src/costwatch/checks/__init__.py) with an
   ID and a one-line description.
3. Add its permissions to [`iam.py`](src/costwatch/iam.py). Read-only only.
4. For `--owners`, add its create event(s) to `CREATE_EVENTS` in
   [`owners.py`](src/costwatch/owners.py); for `--tfstate`, add its Terraform resource types to
   `TERRAFORM_TYPES` in [`iac.py`](src/costwatch/iac.py).
5. Test both what it flags and what it must not flag, and add it to the table in the README.

Guidelines that keep findings trustworthy:

- **Be conservative.** A false positive costs more trust than a missed finding. Skip
  resources you can't judge (no metric data, managed by AWS Backup, and so on).
- **Don't double count.** If another check already reports a resource's cost, don't add it again.
- **Say what the cost means**: full cost, saving, or upper bound.

## Prices

`src/costwatch/data/prices.json.gz` is generated by `scripts/update_prices.py` from the public
AWS price list and refreshed weekly by the *Update prices* workflow. The workflow runs the tests
on the new data and compares it with last week's (`scripts/compare_prices.py`): normal changes
are merged automatically, while large jumps, missing regions or vanishing instance types leave the
pull request open with a `needs review` label. Don't edit the file by hand. To
add a price, extend the script and `pricing.py`, and keep a us-east-1 default in
`pricing.DEFAULTS`.

## Releasing

1. Update `CHANGELOG.md` and bump the version: `uv version X.Y.Z`.
2. Merge to `main`, then create a GitHub release `vX.Y.Z`. The *Release* workflow checks the tag
   matches, runs the tests and publishes to PyPI with trusted publishing.
